# プロジェクト規約（個人ポートフォリオ）

## 何を作っているか

Webアクセシビリティを強みとする制作者の **個人ポートフォリオサイト**。  
見た目のモダンさ（モーション / 3D）と、実装の正しさ・説明可能性を両立させる。

成果物の価値は次の両方にある。

1. 動く・美しい体験
2. **なぜそうしたかを説明できること**（達成基準・代替手段・却下案）

架空企業のコーポレートサイトではない。実在の個人（制作者）の実績・思考・実装力を示す場とする。

## 技術スタック（推奨デフォルト）

開始時に確定し、この節を更新すること。

### 推奨

- **Astro**（コンテンツはサーバー／静的、演出はクライアント島）
- CSSは素のCSS + カスタムプロパティ（CSSフレームワークは原則使わない）
- モーション: **GSAP**（スクロール連動・UI演出）
- 3D: **Three.js**（または React Three Fiber を使う場合は理由を `docs/decisions.md` に残す）
- UIフレームワークは必須にしない。使う場合は島（Islands）に閉じ込め、ページ全体を SPA 化しない

### 絶対に守る姿勢

- **進歩的強化（Progressive Enhancement）**
  - JSオフ / WebGL非対応でも、経歴・作品・連絡手段など主要コンテンツが読めて使える
  - 3Dや演出は「加点」であり、情報の唯一の運び手にしない
- バンドルとメインスレッドを肥大化させない。重い演出は遅延ロードする

## 準拠基準

- **WCAG 2.2 レベルAA** を達成目標とする
- WCAG 2.2 は ISO/IEC 40500:2025 として国際規格化済み
- 国内の JIS X 8341-3 は現行2016年版だが、ISO/IEC 40500:2025 との一致規格とする改正が進行中。本サイトはこれを先取りする
- 達成基準の名称は2026年6月更新のWCAG 2.2日本語訳に準拠する
- 適合表明の文言は「準拠」ではなく **「達成目標とし、試験結果を公開する」** とする

## 絶対規則

1. **コントラスト比を推測で書かない。** 数値を出す場合は必ず計測スクリプト（例: `scripts/contrast.mjs`）の出力のみを根拠とする。暗算・「おそらく」「約」は禁止。最終判定は人間が行う
2. **ネイティブHTML要素を最優先する。** `<button>` `<details>` `<dialog>` `<nav>` で足りるものにARIAを足さない
3. **不要なARIAを付けない。** ARIAを追加する場合は、なぜネイティブで不可能かをコメントで説明すること
4. **`div` や `span` にクリックハンドラを付けない**
5. **`outline: none` を単独で書かない**
6. **`tabindex` に正の値を使わない**（`0` と `-1` のみ）
7. **CSSの色はすべてカスタムプロパティ経由**
8. **固定高さのボックスを作らない**（1.4.12 テキストの間隔 AA）
9. **推測で埋めない。** 判断に迷う箇所は実装を止めて質問すること
10. **動きだけで情報を伝えない。** アニメーション／3Dが止まっても意味が通ること（1.1.1 / 1.4.1 / 2.3.3 関連）
11. **`prefers-reduced-motion: reduce` では、必須でないモーション／3D演出を止めるか静的代替に切り替える**
12. **自動再生する動きには、一時停止・停止・非表示のいずれかを提供する**（2.2.2 一時停止、停止、非表示 A）。5秒超の動きは特に注意

## モーション / 3D の方針（要約）

詳細は `.cursor/rules/motion-webgl.mdc` と `docs/motion-a11y-checklist.md` を正とする。

- Canvas / WebGL は原則 **装飾**。意味のある内容は HTML テキストでも提供する
- ユーザー操作で起動する演出を優先し、無限ループの自動演出は最小限にする
- 前庭障害・てんかんリスクのある強いフラッシュ、激しいカメラシェイクは禁止
- パフォーマンス劣化時は演出を落とす（端末・省電力・低FPS）

## やらないこと

- スクリーンリーダーでの動作を「確認しました」と報告すること（人間が実機で行う）
- 未検証の内容をアクセシビリティ方針ページに書くこと
- 「axeでエラー0件だからAA達成」という結論を書くこと
- 「モダンだから」「映えるから」だけで a11y を後回しにすること
- JS必須のヒーローだけで作品説明を完結させること

## ポートフォリオとしての必須コンテンツ（目安）

ページ構成は変更してよいが、次は到達可能であること。

- 制作者が誰で、何ができるか
- アクセシビリティに関するスタンス（方針・達成目標）
- 作品／事例（各作品にテキストでの説明・役割・工夫）
- 実装解説または意思決定の記録（`docs/decisions.md` とサイト上の導線）
- 連絡手段

## コミット規約

アクセシビリティに関わる変更は、コミットメッセージに達成基準番号を含める。

```
feat(hero): WebGLヒーローに減動代替を追加

- 2.3.3 インタラクションによるアニメーション AAA: prefers-reduced-motion で静的ビジュアルへ切替
- 1.1.1 非テキストコンテンツ A: Canvas に対応するテキスト代替を併置
- 2.2.2 一時停止、停止、非表示 A: 再生中は一時停止ボタンを提供
```

## ドキュメント同期

`docs/decisions.md` に設計判断を記録する。実装を変更したらこのファイルも更新すること。  
形式：日付 / 対象 / 判断内容 / 対応する達成基準 / 選定理由 / 検討した代替案と却下理由

モーションや3Dを新規導入・大きく変えるときは、必ず decisions に残す。

## 応答について

日本語で応答すること。変更を加えた理由を簡潔に添えること。  
動作確認を「しました」と断定せず、人間が確認する手順を提示するに留める。
