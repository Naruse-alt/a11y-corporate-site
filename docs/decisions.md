## 2026-10-26 / 認証済み `/_astro/` に長期 Cache-Control を付ける

- **判断内容**：Basic 認証通過後のレスポンスで、パスが `/_astro/` で始まるものだけ `Cache-Control: private, max-age=31536000, immutable` とする。HTML 等は従来どおり `private, no-store`。401/400 は変更しない。判定は `workers/cache-control.js` の純関数に切り出す。
- **対応する達成基準**：運用・パフォーマンス（UI 達成基準の変更ではない）。ハッシュ付きアセットの再取得と `font-display: swap` が重なり、ページ遷移ごとにフォント差し替えが見えていた。
- **選定理由**：`/_astro/` はファイル名にコンテンツハッシュが付くため、内容が変われば URL も変わる。ブラウザに長く持たせても古い字体が残り続けない。`private` を残し、共有キャッシュには載せない方針は維持する。
- **検討した代替案と却下理由**：Worker を通さず `/_astro/` を静的直出し → `run_worker_first` と Basic 認証の前提が崩れるため却下。全レスポンスを長期キャッシュ → HTML の更新反映と認証後コンテンツの扱いが危ういため却下。フォント差し替え（`font-display` 変更等）→ 別途検討とし、本変更の範囲外。

## 2026-10-25 / セキュリティヘッダーと CSP（ハッシュ）

- **判断内容**：CSP / X-Frame-Options / X-Content-Type-Options / Referrer-Policy / Permissions-Policy / HSTS / X-Robots-Tag を `workers/basic-auth.js`（と `unauthorizedResponse`）で全レスポンスに付与。CSP は `unsafe-inline` なし。`dist/` のインライン script/style から SHA-256 を算出し `workers/csp-policy.generated.js` を生成。CI で生成結果とコミット差分を照合する。
- **対応する達成基準**：運用・セキュリティ（UI 達成基準の変更ではない）。Issue #23。
- **選定理由**：
  - `assets.run_worker_first = true` のため全リクエストが Worker を通る。静的 `_headers` では Worker 生成の 401 にヘッダーが付かない。
  - インライン script（テーマ・ドロワー・お問い合わせ）とページごとの `<style>` があるため、ビルド成果物からハッシュを集約する。
  - HSTS は `max-age=63072000` のみ。配信が workers.dev サブドメインのため preload 登録対象外（親ドメインが preload 済み）で、`includeSubDomains` も実効がない。
- **検討した代替案と却下理由**：
  - `_headers` のみ → 401 に付かないため却下。
  - `script-src 'unsafe-inline'` → 要件に反するため却下。

## 2026-10-25 / Basic 認証の資格情報比較で短絡評価を排除

- **判断内容**：`verifyBasicAuth` でユーザー名・パスワードの `timingSafeEqual` を先に両方評価し、その結果の論理積で 401 を判定する。`timingSafeEqual` 自体は長さ差でも早期 return せず max 長まで比較する既存実装を維持。
- **対応する達成基準**：運用・セキュリティ（UI 達成基準の変更ではない）。Issue #22。
- **選定理由**：`||` の短絡でパスワード比較が省略されると、応答時間差からユーザー名の正否が推測されうる。変数に受けてから判定すれば比較処理は常に両方走る。
- **検討した代替案と却下理由**：ビット演算（`&`）だけで短絡を避ける案 → 可読性が落ちるため、明示的な二段評価を選定。

## 2026-10-18 / Playwright + axe による少数の a11y E2E

- **判断内容**：`@playwright/test` と `@axe-core/playwright` で、壊れると困る挙動だけを E2E 化する。対象は (1) 全ページの axe（WCAG 2.x A/AA タグ）違反ゼロ (2) スキップリンクで `#main` へフォーカス (3) モバイルドロワーを Esc で閉じたときのトリガー復帰 (4) お問い合わせエラーの `aria-invalid` / `aria-describedby`。`astro preview` で静的成果物を検証し、Basic 認証 Worker は対象外。CI は Chromium のみ＋ブラウザキャッシュ。
- **対応する達成基準**：2.4.1 ブロックスキップ A／2.4.3 フォーカス順序 A／2.1.2 キーボードトラップなし A／3.3.1 エラーの特定 A／1.3.1 情報及び関係性 A／4.1.2 名前・役割・値 A（axe は機械検出可能な A/AA の回帰防止。適合の証明には使わない）
- **選定理由**：
  - 数より「なぜこのテストがあるか」を説明できることを優先し、キーボード仕様（`docs/keyboard-specs.md`）とフォームの見せ場に直結するケースに絞る。
  - ネイティブ `<dialog>` / スキップリンク / フォーム ARIA の契約を PR 時点で止められる。
  - preview 配信にすることで Worker シークレットや認証を CI に持ち込まない。
- **検討した代替案と却下理由**：
  - 網羅的なビジュアル／全インタラクション E2E → 保守コストが高く、意図が薄まるため見送り。
  - axe 結果をもって AA 適合と表明 → AGENTS.md 禁止事項のため、回帰ゲートに限定。
  - `wrangler` / Basic 認証経由のテスト → シークレット依存で品質ゲートから外す。
- **E2E で見つかった修正**：`<main id="main">` に `tabindex="-1"` を付与。ページ内リンクだけでは非フォーカス可能要素へフォーカスが移らず、スキップリンクの意図（本文へフォーカス移動）が満たせなかったため。代替案の独自 JS フォーカス移動はネイティブ遷移を壊しやすいので却下。
- **フォーカスリングの扱い**：`#main:focus-visible` と `#main:focus:not(:focus-visible)` で `outline` / `box-shadow` を出さない。`main` は操作要素ではなくスキップリンクの移動先であり、`[tabindex]` 向けの二重リング（2.4.7）が本文全体に付くと見た目のノイズになる。2.4.7 の可視フォーカスはインタラクティブ要素向けのため、操作できないコンテナではリング抑制が妥当（a / button 等のルールは変更しない）。セレクタから `#main` を外す案は UA 既定アウトラインが残るため不十分。独自 JS で次の見出しへフォーカスする案はネイティブページ内リンクを壊しやすいため却下。

- **対応する達成基準**：2.1.2 キーボードトラップなし A／2.4.3 フォーカス順序 A／4.1.2 名前・役割・値 A／3.2.3 一貫したナビゲーション AA／3.2.4 一貫した識別性 AA／2.4.8 現在位置 AAA／1.4.10 リフロー AA
- **選定理由**：
  - `<dialog>`（`showModal()`）は「フォーカストラップ・Escape・背景 inert・閉鎖時のフォーカス復帰」をネイティブで提供し、独自 ARIA/JS を最小化できる（規約「ネイティブ最優先」に合致）。
  - ナビの単一情報源化で、ヘッダー／ドロワー／フッターの表記ゆれを防ぎ一貫性を担保。
  - 進歩的強化により JS 無効でも全ページへ到達できる（規約の必須要件）。
- **検討した代替案と却下理由**：
  - `<button aria-expanded>` ＋ 自作フォーカストラップ → JS と ARIA が増え、バグ余地も大きいため却下。`<dialog>` で代替可能。
  - CSS のみのチェックボックスハック → セマンティクスが崩れ、フォーカス管理も不十分なため却下。
  - `<details>/<summary>` によるドロワー → モーダルに必要な背景 inert・フォーカストラップを持たないため却下。

## 2026-08-28 / コントラスト検証ツール `scripts/contrast.mjs`

- **判断内容**：`src/styles/tokens.css` を単一の情報源として読み取り、意味のある前景／背景ペアの WCAG コントラスト比を機械判定する Node スクリプトを実装した。CLI で任意 2 色の検証も可能。
- **対応する達成基準**：1.4.3 コントラスト（最低限）AA、1.4.11 非テキストのコントラスト AA
- **選定理由**：絶対規則により、コントラスト比は推測・暗算で書かず、スクリプト出力を唯一の根拠とする必要があるため。
- **検討した代替案と却下理由**：
  - 既存 npm パッケージの利用 → 依存を増やさず、判定ロジックを説明可能な形で内製する方が本ポートフォリオの趣旨（なぜそうしたかを説明できること）に合致するため却下。

## 2026-08-28 / カラートークンとテーマ設計

- **判断内容**：色はすべて `tokens.css` のカスタムプロパティ経由とし、ライト（`:root`）／ダーク（`:root[data-theme="dark"]` および `@media (prefers-color-scheme: dark)`）の両モードを用意した。全ペアが `scripts/contrast.mjs` で AA 基準を満たすことを確認済み（実行出力を根拠とする）。
- **対応する達成基準**：1.4.3 コントラスト（最低限）AA、1.4.1 色の使用 A（本文リンクは下線併用）
- **選定理由**：色のみに依存しない表現と、ライト／ダーク両対応を規約が要求するため。
- **検討した代替案と却下理由**：
  - 単一テーマのみ → 規約でライト・ダーク両維持が必須のため却下。

## 2026-08-28 / フォーカスリングの二重アウトライン

- **判断内容**：`:focus-visible` に「内側=明色 outline＋外側=暗色 box-shadow」の二重リングを与え、`:focus` にフォールバックを用意した。`outline: none` を単独では書かない。
- **対応する達成基準**：2.4.7 フォーカスの可視化 A、2.4.11 フォーカスの外観（新規）
- **選定理由**：明背景・暗背景の双方でフォーカスが視認できる必要があるため。
- **検討した代替案と却下理由**：
  - 単色 outline のみ → 背景色によっては視認性が不足するため却下。

## 2026-08-28 / テーマ切替の進歩的強化

- **判断内容**：テーマ切替ボタンは JavaScript で生成して挿入し、JS 無効時は OS 設定（`@media`）に従う。ボタンのラベルテキスト自体が操作内容を伝えるため追加の ARIA は付けない。
- **対応する達成基準**：4.1.2 名前・役割・値 A（ネイティブ `<button>` を使用）
- **選定理由**：JS 無効時に「押しても何も起きない死んだ UI」を残さないため。ネイティブ要素優先の規約にも合致。
- **検討した代替案と却下理由**：
  - サーバ側でボタンを常時描画 → JS 無効時に機能しないコントロールが残るため却下。
  - `aria-pressed` の付与 → 既定状態が「OS 追従」で二値のトグルに収まらず、ラベル文言で状態を明示する方が誤解が少ないため却下。
