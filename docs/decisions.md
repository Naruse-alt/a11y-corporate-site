## 2026-09-07 / フォントを IBM Plex Sans JP に刷新

- **判断内容**：サイト全体のサンセリフをシステムスタックから **IBM Plex Sans JP**（ウェイト 400 / 700）へ変更。`@fontsource/ibm-plex-sans-jp` でセルフホストし、`font-display: swap` を利用。Latin + Japanese サブセットのみ読み込む。
- **対応する達成基準**：1.4.12 テキストの間隔 AA（固定高さに依存しない既存設計を維持）／1.4.4 テキストのサイズ変更 AA（相対単位の既存スケールを維持）
- **選定理由**：
  - システムフォント依存だと OS によって古く・無難に見えやすく、ポートフォリオの視覚品質が安定しない。
  - IBM Plex Sans JP は字面がモダンで、技術系コーポレートの「硬さ」も出しやすい。
  - サードパーティ（Google Fonts CDN）に依存せずセルフホストし、プライバシーとオフライン耐性を確保する。
  - ウェイトは 400/700 に限定し、転送量と CLS リスクを抑える。
- **検討した代替案と却下理由**：
  - Zen Kaku Gothic New → よりデザイン寄りだが、堅実さの優先度では Plex に劣るため見送り。
  - Noto Sans JP の Web フォント化のみ → 変化が小さく「古臭さ」の改善が弱いため却下。
  - Google Fonts CDN → 実装は簡単だが外部依存が増えるため、セルフホストを選定。
  - 見出し専用の別ラテンフォント併用 → まずは1ファミリーで統一し、複雑化を避ける。

## 2026-09-06 / ホームヒーローを二分割＋イラスト化

- **判断内容**：トップヒーローを「左：文言／右：イラスト」の二分割に変更。アクセシビリティ×協働を示すフラットイラスト（`public/images/hero-inclusive-web.webp|.png`）を追加。**デスクトップでは既定で横並び**、`max-width: 40rem` 以下だけ縦積み（OS／ブラウザ拡大で 48rem 未満の CSS 幅になり PC でも縦積みになる問題への対策）。イラストに短い `alt` を付与。軽い浮遊アニメは `prefers-reduced-motion: no-preference` のときのみ。
- **対応する達成基準**：1.1.1 非テキストコンテンツ A／1.4.10 リフロー AA／1.4.12 テキストの間隔 AA／2.3.3 アニメーションからのインタラクションによるトリガー AA（低減）／1.4.1 色の使用 A（意味はテキストが担う）
- **選定理由**：
  - 承認済みのミニマル基盤を保ちつつ、ヒーローに視覚的な遊びとブランド感を足すため。
  - 全幅オーバーレイ案より、テキストコントラストを画像に依存させず安全。
  - イラストは写真よりトーンをブランド色（ブルー系）に揃えやすい。
  - モバイルファーストの `min-width: 48rem` だと、拡大表示のノート PC で意図せず縦積みになるため、横並びを既定にした。
- **検討した代替案と却下理由**：
  - 全幅背景画像＋文字重ね → コントラスト管理が難しく、バッジ類も増えやすいため却下。
  - 抽象グラデのみ強化 → 視覚アンカーが弱く「遊び心」にならないため却下。
  - 装飾として `alt=""` のみ → 包摂的な人物表現を含むため、短い代替テキストを残す方が丁寧と判断。
  - ブレークポイントをナビと同じ 48rem のまま維持 → 実機（拡大あり PC）で縦積みになり、二分割の意図が崩れるため却下。
## 2026-09-03 / お問い合わせフォーム（送信なしデモ）

  - サーバー／アダプター導入 → 静的方針から外れるため却下。
  - 成功後にフォームをリセット → 再入力を強いるため却下。

## 2026-08-31 / FAQ ページ（ネイティブ `<details>` / `<summary>`）

- **判断内容**：見せ場ページの第1弾として `/faq/` を追加。Q&A はネイティブ `<details>` / `<summary>` のアコーディオンとし、開閉用の独自 ARIA（`aria-expanded` 等）は付けない。カテゴリは `h2`（方針・対応範囲／制作プロセス／試験・適合表明）で分け、ナビは `src/data/nav.ts` に「よくある質問」を追加。「すべて開く/閉じる」は今回スコープ外。
- **対応する達成基準**：1.3.1 情報及び関係性 A／2.1.1 キーボード A／2.4.3 フォーカス順序 A／2.4.7 フォーカスの可視化 A／2.5.8 ターゲットサイズ（最小）AA／3.2.3 一貫したナビゲーション AA／3.2.4 一貫した識別性 AA／1.4.10 リフロー AA／1.4.12 テキストの間隔 AA
- **選定理由**：
  - `<details>` は開閉・キーボード・開示状態をブラウザが持つため、独自 JS/ARIA を最小化できる（規約「ネイティブ最優先」に合致）。
  - ドロワー（`<dialog>`）に続く見せ場として、「なぜ ARIA を付けないか」を説明しやすい。
  - JS 無効でも開閉できる（進歩的強化の説明が簡潔）。
  - 見た目はカードではなく区切り線＋ `summary` の 44px ターゲットで、既存プリミティブと調和させる。
- **検討した代替案と却下理由**：
  - ボタン＋パネル＋`aria-expanded` 自作アコーディオン → ネイティブで足りるのに ARIA/JS が増えるため却下。
  - すべて展開した静的 Q&A のみ → 開閉パターンを見せ場として示せないため却下。
  - お問い合わせフォームを先に実装 → エラー処理・ライブリージョン等の判断点が多く、ネイティブ優先の次の一歩としては FAQ の方が単純で説明しやすいため後回し。
  - `<dialog>` で各回答をモーダル表示 → FAQ にモーダルは過剰。背景 inert も不要のため却下。
  - 「すべて開く/閉じる」制御 → 今回は不要。必要なら別判断とする。

## 2026-08-31 / テーマ切替をアイコンボタン化（控えめな配置）

- **判断内容**：テキスト＋ピル型で主張が強すぎたテーマ切替を、アイコンのみ（月＝ダークへ / 太陽＝ライトへ）の 44×44 の控えめなボタンに変更。通常は枠・背景なし、ホバー時のみ淡い背景。
- **対応する達成基準**：2.5.8 ターゲットサイズ（最小）AA（44px 確保）／4.1.2 名前・役割・値 A（`aria-label` で名前を担保）／1.4.11 非テキストのコントラスト AA（アイコンは currentColor）
- **選定理由**：デザイン上の主張を抑えつつ、慣習的なアイコンで操作内容を分かりやすく示すため。アイコンのみは可視テキストが無く名前を持てないため、例外的に `aria-label`（＋補助的に `title`）を付与。
- **検討した代替案と却下理由**：
  - テキストラベルを小さくする案 → 主張は下がるがデザインの洗練度で劣るため却下。
  - `aria-pressed` の付与 → 既定が「OS 追従」で二値に収まらず、次の操作を表すラベルの方が誤解が少ないため却下。
  - アイコン＋視覚非表示テキスト → `aria-label` で十分かつ簡潔なため不採用。

- **選定理由**：
  - トークンとプリミティブを先に固めることで、以降のページが自動的に同じ視覚言語を継承でき、手戻りと不整合を防げる。
  - 追加した色役割（面2・強調・淡境界）はすべて `scripts/contrast.mjs` で検証（全22ペア合格）。数値はスクリプト出力を根拠とする。

  - 見出しへ日本語ウェブフォント導入 → 表示速度・CLS のトレードオフが大きく、まずはシステムフォントで階層設計を優先（将来の選択肢として保留）。
  - 第2アクセントカラー（ティール等）の追加 → 意味を担う色が増えコントラスト管理が複雑化するため見送り。ブルー系を単一アクセントとして継続。

## 2026-08-28 / カラートークンとテーマ設計

- **判断内容**：色はすべて `tokens.css` のカスタムプロパティ経由とし、ライト（`:root`）／ダーク（`:root[data-theme="dark"]` および `@media (prefers-color-scheme: dark)`）の両モードを用意した。全ペアが `scripts/contrast.mjs` で AA 基準を満たすことを確認済み（実行出力を根拠とする）。
- **対応する達成基準**：1.4.3 コントラスト（最低限）AA、1.4.1 色の使用 A（本文リンクは下線併用）
- **選定理由**：色のみに依存しない表現と、ライト／ダーク両対応を規約が要求するため。
- **検討した代替案と却下理由**：
  - 単一テーマのみ → 規約でライト・ダーク両維持が必須のため却下。

## 2026-08-28 / フォーカスリングの二重アウトライン

- **判断内容**：`:focus-visible` に「内側=明色 outline＋外側=暗色 box-shadow」の二重リングを与え、`:focus` にフォールバックを用意した。`outline: none` を単独では書かない。
- **対応する達成基準**：2.4.7 フォーカスの可視化 A、2.4.11 フォーカスの外観（新規）
- **選定理由**：明背景・暗背景の双方でフォーカスが視認できる必要があるため。
- **検討した代替案と却下理由**：
  - 単色 outline のみ → 背景色によっては視認性が不足するため却下。

## 2026-08-28 / テーマ切替の進歩的強化

- **判断内容**：テーマ切替ボタンは JavaScript で生成して挿入し、JS 無効時は OS 設定（`@media`）に従う。ボタンのラベルテキスト自体が操作内容を伝えるため追加の ARIA は付けない。
- **対応する達成基準**：4.1.2 名前・役割・値 A（ネイティブ `<button>` を使用）
- **選定理由**：JS 無効時に「押しても何も起きない死んだ UI」を残さないため。ネイティブ要素優先の規約にも合致。
- **検討した代替案と却下理由**：
  - サーバ側でボタンを常時描画 → JS 無効時に機能しないコントロールが残るため却下。
  - `aria-pressed` の付与 → 既定状態が「OS 追従」で二値のトグルに収まらず、ラベル文言で状態を明示する方が誤解が少ないため却下。
