## 2026-08-31 / デザイン基盤の刷新（洗練されたミニマル）

- **判断内容**：サブページ拡充前に視覚言語を確定するため、トークンを拡張（流体タイプスケール `--text-*`、余白の拡張、`--color-surface-2`／`--color-border-subtle`／`--color-primary-strong`、角丸・影・トランジション）し、共通プリミティブ（`.button`／`.card`／`.section`／`.eyebrow`／`.lead`／`.callout`／`.prose`）を `global.css` に整備。ヘッダーへロゴマーク追加＋スティッキー化、トップにヒーロー（淡色パネル＋装飾）とアイコン付きカード、方針ページに prose とコールアウトを適用した。
- **対応する達成基準**：1.4.3 コントラスト（最低限）AA／1.4.11 非テキストのコントラスト AA／1.4.1 色の使用 A／1.4.10 リフロー AA／1.4.12 テキストの間隔 AA／2.4.7 フォーカスの可視化 A
- **選定理由**：
  - トークンとプリミティブを先に固めることで、以降のページが自動的に同じ視覚言語を継承でき、手戻りと不整合を防げる。
  - 追加した色役割（面2・強調・淡境界）はすべて `scripts/contrast.mjs` で検証（全22ペア合格）。数値はスクリプト出力を根拠とする。
  - 影は forced-colors で無効化されるため、境界線でも構造を担保（`@media (forced-colors: active)` でカード境界を明示）。装飾要素は `aria-hidden`。
  - 流体タイプ（clamp）と rem 基準で、拡大・狭幅でも固定高さを作らず破綻を防ぐ。
- **検討した代替案と却下理由**：
  - 最後にまとめて装飾を足す案 → 全ページ再調整が必要で不整合・コスト増のため却下。トークン駆動の今のうちに方向性を固める方が安全。
  - 見出しへ日本語ウェブフォント導入 → 表示速度・CLS のトレードオフが大きく、まずはシステムフォントで階層設計を優先（将来の選択肢として保留）。
  - 第2アクセントカラー（ティール等）の追加 → 意味を担う色が増えコントラスト管理が複雑化するため見送り。ブルー系を単一アクセントとして継続。

## 2026-08-31 / モバイルナビの導入と共通土台の刷新

- **判断内容**：サブページ拡充に先立ち、(1) ナビ項目を単一情報源 `src/data/nav.ts` に集約、(2) モバイル用ドロワーをネイティブ `<dialog>` で実装、(3) ハンバーガーは進歩的強化（JS無効時はインラインナビにフォールバック）、(4) フッターナビとパンくず（`Breadcrumb.astro`）を追加した。ブレークポイントは 48rem。
- **対応する達成基準**：2.1.2 キーボードトラップなし A／2.4.3 フォーカス順序 A／4.1.2 名前・役割・値 A／3.2.3 一貫したナビゲーション AA／3.2.4 一貫した識別性 AA／2.4.8 現在位置 AAA／1.4.10 リフロー AA
- **選定理由**：
  - `<dialog>`（`showModal()`）は「フォーカストラップ・Escape・背景 inert・閉鎖時のフォーカス復帰」をネイティブで提供し、独自 ARIA/JS を最小化できる（規約「ネイティブ最優先」に合致）。
  - ナビの単一情報源化で、ヘッダー／ドロワー／フッターの表記ゆれを防ぎ一貫性を担保。
  - 進歩的強化により JS 無効でも全ページへ到達できる（規約の必須要件）。
- **検討した代替案と却下理由**：
  - `<button aria-expanded>` ＋ 自作フォーカストラップ → JS と ARIA が増え、バグ余地も大きいため却下。`<dialog>` で代替可能。
  - CSS のみのチェックボックスハック → セマンティクスが崩れ、フォーカス管理も不十分なため却下。
  - `<details>/<summary>` によるドロワー → モーダルに必要な背景 inert・フォーカストラップを持たないため却下。

## 2026-08-28 / コントラスト検証ツール `scripts/contrast.mjs`

- **判断内容**：`src/styles/tokens.css` を単一の情報源として読み取り、意味のある前景／背景ペアの WCAG コントラスト比を機械判定する Node スクリプトを実装した。CLI で任意 2 色の検証も可能。
- **対応する達成基準**：1.4.3 コントラスト（最低限）AA、1.4.11 非テキストのコントラスト AA
- **選定理由**：絶対規則により、コントラスト比は推測・暗算で書かず、スクリプト出力を唯一の根拠とする必要があるため。
- **検討した代替案と却下理由**：
  - 既存 npm パッケージの利用 → 依存を増やさず、判定ロジックを説明可能な形で内製する方が本ポートフォリオの趣旨（なぜそうしたかを説明できること）に合致するため却下。

## 2026-08-28 / カラートークンとテーマ設計

- **判断内容**：色はすべて `tokens.css` のカスタムプロパティ経由とし、ライト（`:root`）／ダーク（`:root[data-theme="dark"]` および `@media (prefers-color-scheme: dark)`）の両モードを用意した。全ペアが `scripts/contrast.mjs` で AA 基準を満たすことを確認済み（実行出力を根拠とする）。
- **対応する達成基準**：1.4.3 コントラスト（最低限）AA、1.4.1 色の使用 A（本文リンクは下線併用）
- **選定理由**：色のみに依存しない表現と、ライト／ダーク両対応を規約が要求するため。
- **検討した代替案と却下理由**：
  - 単一テーマのみ → 規約でライト・ダーク両維持が必須のため却下。

## 2026-08-28 / フォーカスリングの二重アウトライン

- **判断内容**：`:focus-visible` に「内側=明色 outline＋外側=暗色 box-shadow」の二重リングを与え、`:focus` にフォールバックを用意した。`outline: none` を単独では書かない。
- **対応する達成基準**：2.4.7 フォーカスの可視化 A、2.4.11 フォーカスの外観（新規）
- **選定理由**：明背景・暗背景の双方でフォーカスが視認できる必要があるため。
- **検討した代替案と却下理由**：
  - 単色 outline のみ → 背景色によっては視認性が不足するため却下。

## 2026-08-28 / テーマ切替の進歩的強化

- **判断内容**：テーマ切替ボタンは JavaScript で生成して挿入し、JS 無効時は OS 設定（`@media`）に従う。ボタンのラベルテキスト自体が操作内容を伝えるため追加の ARIA は付けない。
- **対応する達成基準**：4.1.2 名前・役割・値 A（ネイティブ `<button>` を使用）
- **選定理由**：JS 無効時に「押しても何も起きない死んだ UI」を残さないため。ネイティブ要素優先の規約にも合致。
- **検討した代替案と却下理由**：
  - サーバ側でボタンを常時描画 → JS 無効時に機能しないコントロールが残るため却下。
  - `aria-pressed` の付与 → 既定状態が「OS 追従」で二値のトグルに収まらず、ラベル文言で状態を明示する方が誤解が少ないため却下。
